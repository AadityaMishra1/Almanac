## Storage Approach

**Decision: Use Prisma with SQLite for local development, PostgreSQL-ready for production**

**Rationale:**
- Prisma already in node_modules (@prisma/client in tsconfig.tsbuildinfo), familiar to Next.js ecosystem
- SQLite for zero-config local development (matches solo developer + quick iteration philosophy)
- Schema easily migrates to PostgreSQL for Vercel deployment
- Type-safe queries with TypeScript integration
- Existing Zod validation patterns (lib/events.ts) integrate cleanly with Prisma

**Alternative considered:** Direct SQL with better-sqlite3
**Why not:** No type safety, manual migration management, more boilerplate

## Schema Design

**Event Model:**
- `id`: UUID primary key (not auto-increment for external event ID mapping)
- `title`, `date`, `time`, `type`, `description`: Core event data (extends existing SyllabusEvent)
- `source`: Enum (ALMANAC | GOOGLE_CALENDAR) - distinguishes creation origin
- `googleEventId`: String? - maps to external Google Calendar event for sync
- `editable`: Boolean - computed field based on source (true for ALMANAC, false for GOOGLE_CALENDAR)
- `courseId`: Foreign key to Course model
- `createdBy`: User reference (for multi-user future, stub for now)
- `createdAt`, `updatedAt`: Timestamps for audit trail

**Course Model:**
- `id`: UUID primary key
- `code`: String (e.g., "CSC 316") - unique identifier
- `name`: String (e.g., "Data Structures")
- `color`: String? - hex color for calendar UI (Phase 3)
- `semester`: String (e.g., "Spring 2026")
- `events`: Relation to Event[]

**EventSource Enum:**
- `ALMANAC`: Created by Almanac (PDF extraction or manual creation)
- `GOOGLE_CALENDAR`: Imported from external Google Calendar

**Why this design:**
- `source` field enables requirement DATA-02 (distinguish Almanac vs external)
- `editable` computed from source enables requirement DATA-03 (permission enforcement)
- `googleEventId` enables bidirectional sync (Phase 4) without duplicates
- Course relationship enables filtering, color-coding, and organization
- UUID ids prevent collision with external event IDs

## Permission Enforcement Pattern

**Server-side validation in mutations:**
- All update/delete operations check `event.source === 'ALMANAC'` before proceeding
- External events (source: GOOGLE_CALENDAR) return error on mutation attempts
- Read operations (queries) have no restrictions

**Client-side UI hints:**
- Editable flag controls button enabled/disabled state
- External events rendered with read-only indicator (lock icon, grayed out)

**Implementation:**
- Prisma middleware (not used initially - adds complexity)
- Explicit checks in server actions/API routes (follows existing pattern from calendar.ts)

## Testing Strategy

**Unit Tests (deferred to implementation):**
- Schema validation with Prisma Client
- Permission check logic in server actions
- Date/time parsing and normalization

**Integration Tests (manual verification):**
- Create Almanac event → editable=true, can update
- Create Google Calendar event → editable=false, update fails
- Query both types → both returned
- Attempt to modify external event → returns error

**Migration Strategy:**
- Prisma migrate dev for local development
- Prisma migrate deploy for production
- Shadow database for safe migration testing

<task type="auto">

  <files>
    prisma/schema.prisma
  </files>
  <action>
Replace the contents of `prisma/schema.prisma` with:

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")
}

enum EventSource {
  ALMANAC
  GOOGLE_CALENDAR
}

model Course {
  id        String   @id @default(uuid())
  code      String   @unique // e.g., "CSC 316"
  name      String   // e.g., "Data Structures"
  color     String?  // hex color for calendar UI (e.g., "#3b82f6")
  semester  String   // e.g., "Spring 2026"

  events    Event[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("courses")
}

model Event {
  id              String      @id @default(uuid())
  title           String
  date            String      // ISO 8601 date (YYYY-MM-DD)
  time            String?     // ISO 8601 time (HH:MM) or null for all-day
  type            String      // e.g., "exam", "assignment", "quiz", "reading"
  description     String?

  // Source authority and permissions
  source          EventSource @default(ALMANAC)
  googleEventId   String?     @unique // Maps to Google Calendar event ID for sync
  editable        Boolean     @default(true) // Computed: true for ALMANAC, false for GOOGLE_CALENDAR

  // Relationships
  courseId        String
  course          Course      @relation(fields: [courseId], references: [id], onDelete: Cascade)

  // Audit fields
  createdAt       DateTime    @default(now())
  updatedAt       DateTime    @updatedAt

  @@index([courseId])
  @@index([date])
  @@index([source])
  @@map("events")
}
```

**Schema design decisions:**

1. **EventSource enum**: Distinguishes Almanac-created events from external Google Calendar events (DATA-02).

2. **editable field**: Defaults to true for ALMANAC events, set to false for GOOGLE_CALENDAR events. This enforces read-only permissions (DATA-03).

3. **googleEventId**: Unique constraint prevents duplicate event imports during sync (Phase 4). Nullable because Almanac-created events may not yet be synced.

4. **Course relationship**: Enables filtering by course, color-coding in calendar UI (Phase 3), and logical grouping.

5. **date as String**: Keeps ISO 8601 format (YYYY-MM-DD) consistent with existing `lib/events.ts` `coerceToIsoDate()` logic. Avoids timezone issues with SQLite DateTime.

6. **time as String?**: Nullable for all-day events (current behavior). Future enhancement: support specific times (HH:MM format).

7. **Cascade delete**: Deleting a course deletes all associated events (prevents orphaned events).

8. **Indexes**: Optimize common queries (events by course, by date, by source).

**Why uuid() not cuid():**
- UUIDs standard, widely recognized, compatible with Google Calendar event IDs
- cuid() requires additional package, adds dependency

**Why string dates not DateTime:**
- Existing codebase uses ISO string dates (lib/events.ts)
- SQLite DateTime has timezone quirks
- Consistency with SyllabusEvent type (date: string)
