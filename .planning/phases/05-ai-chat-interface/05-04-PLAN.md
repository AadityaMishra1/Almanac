**prisma/schema.prisma:**
Add a new `ChatCommand` model to persist undo history:

```prisma
model ChatCommand {
  id          String   @id @default(uuid())
  type        String   // 'modify' | 'delete' | 'create'
  description String   // Human-readable: "Moved CSC 316 Midterm to March 15"
  eventId     String   // The event that was affected
  beforeState String?  // JSON serialized EventSnapshot (null for create)
  afterState  String?  // JSON serialized EventSnapshot (null for delete)
  undone      Boolean  @default(false)

  createdAt   DateTime @default(now())

  @@index([createdAt])
  @@map("chat_commands")
}
```

After modifying the schema, run `npx prisma db push` to sync (SQLite, no migration needed for dev).

**lib/chat/commands.ts:**
Create the command persistence and undo execution layer:

1. `saveCommand(data: { type, description, eventId, beforeState?, afterState? }): Promise<ChatCommand>`
   - Persists a new ChatCommand record to database using prisma
   - `beforeState` and `afterState` are JSON-stringified EventSnapshot objects
   - Returns the created record

2. `getRecentCommands(limit?: number): Promise<ChatCommand[]>`
   - Fetches recent commands, newest first, default limit 20
   - `prisma.chatCommand.findMany({ orderBy: { createdAt: 'desc' }, take: limit })`

3. `undoCommand(commandId: string): Promise<{ ok: true } | { ok: false; error: string }>`
   - Fetch the command record
   - If already undone, return error: "This operation has already been undone."
   - Switch on command.type:

     **modify undo**: Restore the beforeState
     - Parse `beforeState` JSON to get EventSnapshot
     - Update event in database: `prisma.event.update({ where: { id: command.eventId }, data: { title, date, time, type } })`
     - If event has googleEventId, update Google Calendar too (get session, getCalendarClient, patch -- same pattern as resolveConflict in calendar.ts)

     **delete undo**: Re-create the deleted event
     - Parse `beforeState` JSON to get full EventSnapshot
     - Look up courseId by courseName (from snapshot) -- find matching course
     - Create event: `prisma.event.create({ data: { id: command.eventId, title, date, time, type, courseId, source: 'ALMANAC', editable: true } })`
     - Use the ORIGINAL event ID so any Google Calendar references stay valid
     - Note: Do NOT attempt to re-create in Google Calendar (it was deleted there too). The next sync will push it if needed.

     **create undo**: Delete the created event
     - Delete event: `prisma.event.delete({ where: { id: command.eventId } })`
     - If event has googleEventId, delete from Google Calendar too (graceful)

   - Mark command as undone: `prisma.chatCommand.update({ where: { id: commandId }, data: { undone: true } })`
   - Return `{ ok: true }`

For Google Calendar operations in undo:
- Import `getServerSession` and `authOptions` for session access
- Import `getCalendarClient` from `@/lib/google`
- Wrap Google Calendar calls in try-catch -- if they fail, still succeed locally (graceful degradation)
- Log warnings for GCal failures with `console.warn`

IMPORTANT: The undoCommand function runs in an API route context (not a server action), so use `getServerSession(authOptions)` directly -- this works in API routes.
