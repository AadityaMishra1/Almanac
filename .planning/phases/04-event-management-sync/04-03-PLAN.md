**`lib/sync/detect-conflicts.ts` — Detect field-level conflicts:**

Export `detectConflicts(localEvents, googleEvents)`:
- For events that exist in BOTH systems (matched by googleEventId):
  - Compare title, date, time, description fields
  - If any field differs, create a ConflictRecord:
    ```typescript
    interface FieldDiff {
      field: string; // 'title' | 'date' | 'time' | 'description'
      local: string | null;
      google: string | null;
    }

    interface ConflictRecord {
      eventId: string; // local event ID
      googleEventId: string;
      localTitle: string;
      googleTitle: string;
      diffs: FieldDiff[];
    }
    ```
  - Only include fields that actually differ (from CONTEXT.md: "Changed fields only, hide identical fields")
- Return `ConflictRecord[]`

**Update `lib/sync/sync-engine.ts`:**
- After fetching Google events, before pushing, call `detectConflicts`
- If conflicts found, include them in SyncResult:
  ```typescript
  interface SyncResult {
    ok: boolean;
    fetched: number;
    pushed: number;
    skippedDuplicates: number;
    conflicts: ConflictRecord[];
    errors: string[];
  }
  ```
- Do NOT auto-resolve conflicts. Return them for UI to handle.
- Skip conflicting events in both fetch-import and push phases (don't overwrite either side)

**`components/calendar/conflict-resolution-modal.tsx` — Resolution UI:**

A blocking modal (from CONTEXT.md: "Blocking modal on sync — pauses sync when conflict detected") that shows when sync returns conflicts.

**For each conflict:**
- Show event title as header
- Show diff table: field name | Almanac value | Google value
- Changed fields highlighted (e.g., different background color for cells that differ)
- Three resolution buttons per conflict:
  - "Keep Almanac" — update Google Calendar with local values
  - "Keep Google" — update local database with Google values
  - "Merge" — show individual field selectors (radio buttons) to pick per-field

**Merge mode:**
- For each differing field, show radio group: "Almanac" | "Google"
- Pre-select "Almanac" for all fields (default to keeping local changes)
- "Apply Merge" button executes the merge

**On resolution:**
- Call appropriate server actions: `updateEvent` for local changes, Google Calendar API for Google changes
- Add `resolveConflict(eventId: string, resolution: { field: string; value: string | null }[])` server action to `app/server-actions/calendar.ts`:
  - Updates local event with resolved values
  - Updates Google Calendar event with resolved values (using `calendar.events.patch`)
- After all conflicts resolved, call `router.refresh()`

**CalendarView integration:**
- After `handleSync` completes, check `result.conflicts.length > 0`
- If conflicts exist, set `conflictsToResolve` state and open ConflictResolutionModal
- Pass `onResolved` callback that resets conflicts and refreshes

**Modal design (from CONTEXT.md: "feel like a diff view tool"):**
- Use a clean table layout with two columns (Almanac | Google)
- Differing values: left column in blue tint, right column in amber tint
- Use monospace or slightly different font weight for values to make comparison easy
- Step through conflicts one at a time if multiple (1 of N, with Next/Previous)
